# deordinal

文章・コードコメント・Python docstring の先頭にある順序ラベルを検出する Rust 製 CLI。順序が必要かどうかは判定しません。

```sh
cargo install --path .
deordinal check                 # カレントディレクトリを再帰的に検査
deordinal check README.md src  # 明示したファイル・ディレクトリを検査
deordinal check -v              # 診断がないファイルも検査結果を表示
deordinal init                  # カレントディレクトリに設定ファイルを作成
```

`パス:行:列: ルールID: 理由` を出力します。列は UTF-8 バイト位置ではなく Unicode 文字数を基準とする 1 始まりです。`-v` / `--verbose` を指定すると、診断の有無にかかわらず検査できた対象ファイルごとの件数と全体の集計を標準出力に表示します。読み取れなかったファイルや対象外の拡張子は検査済み件数に含めません。終了コードは警告なし `0`、警告あり `1`、読み取り失敗・不正な ignore・引数エラーは `2`。診断は標準出力、エラーは標準エラーに出力します。

対象は `.md`、`.js` / `.jsx` / `.mjs` / `.cjs`、`.ts` / `.tsx` / `.mts` / `.cts`、`.py` / `.pyi`。ディレクトリ探索では既定で `.gitignore` を尊重し、隠しファイルとシンボリックリンクは辿りません。明示したファイルは ignore ファイルにかかわらず検査し、明示したファイルへのシンボリックリンクは読み取ります。対象拡張子の非 UTF-8 ファイルはエラーです。

## ルール

- `deordinal/ordered-list`: Markdown の番号付きリストをリストごとに検出。入れ子は別リスト。
- `deordinal/ordinal-prefix`: `1. 概要`、`1: 概要`、`A) 概要`、`(1) 概要`、`① 概要` などの文章先頭ラベル。
- `deordinal/keyword-prefix`: `Step 1`、`Phase A`、`ステップ 1` などの文章先頭ラベル。ラベルだけの見出しも対象。

数値・単位・年・バージョンに見える表現を一部除外しますが、意味による必要性の判定はしません。文中の参照表現は検査しません。

Markdown では見出し、本文、リスト、引用を検査します。コードブロック、インラインコード、frontmatter、表、HTML 本文、Markdown 内のコードは検査しません。装飾でラベル自体が分断された場合（例: `**1.** 概要`）も検査しません。JavaScript / TypeScript / Python では構文木上のコメントを、Python ではさらにモジュール・クラス・関数（非同期関数を含む）の最初の文である文字列リテラルの各行を検査します。通常の文字列やコードは検査しません。

## Markdown の ignore

必要な順序には、単独行の HTML コメントによる理由付き範囲指定またはファイル指定を使います。

````md
<!-- deordinal-ignore-start: この手順は順番に実行する必要がある -->
1. サービスを停止する
2. バックアップを取得する
<!-- deordinal-ignore-end -->
````

ファイル全体を除外する場合、BOM と空行を除く文書の最初の内容を以下にします。

````md
<!-- deordinal-ignore-file: 順序付きの操作手順書である -->
````

理由欠落、対応しない終了、閉じられない開始、入れ子、先頭以外のファイル指定、未対応の `deordinal-ignore` は `deordinal/ignore` エラーになります。ignore のエラーは抑制されません。コード内コメントに ignore 記法はありません。
